# Vibe Coding 时代：面试与能力评估新框架

> 从"古法编码"到"AI-Native 开发"，考察维度的根本性转变

---

## 一、范式转移：什么变了？

### 过去考察的（已内化到 AI）
| 维度 | 传统考察方式 | AI 时代状态 |
|------|-------------|------------|
| 算法能力 | LeetCode 刷题 | Claude Code 秒解 |
| 数据结构 | 手写实现 | 自然语言描述即可 |
| 编码规范 | 代码 Review | AI 自动生成符合规范的代码 |
| 专业知识 | 八股文问答 | RAG + LLM 即时检索 |

### 现在考察的（人的核心价值）
- **架构能力** — 系统设计的战略眼光
- **工程能力** — 持续交付的工程素养
- **AI 管理能力** — 多 Agent 协作的编排能力

---

## 二、新面试问题集

### Level 1：效率优化

#### Token 效率
> "刚才你做的工作花了 10M Token，如何在 1M 内解决？"

考察点：
- 是否理解 Token 消耗的主要来源
- 能否设计更精简的 Context 结构
- 是否掌握 Prompt 压缩技巧

#### 时间效率
> "刚才你花了 1 个小时解决问题，如果想 10min 搞定，该怎么做？"

考察点：
- 任务拆解的颗粒度把握
- 并行化的设计能力
- 快速验证假设的方法

---

### Level 2：问题形态识别

#### 解空间重构
> "你有没有意识到问题的'形态'？有没有在一开始就选对解法路径？"

核心洞察：
```
低层次：AI 是更快的键盘 → 加速执行
高层次：AI 是解空间的放大器 → 重构问题 → 再执行
```

考察点：
- 面对问题时首先思考什么
- 能否识别问题的本质结构
- 是否能预判不同解法的路径成本

> **关键认知**：Token 花多少、时间用多久，往往在第一步就已经被决定了。

---

### Level 3：任务拆解与编排

#### 拆解逻辑
> "你是怎么拆这个任务的？为什么要这么拆？"

考察点：
- 拆解的颗粒度是否合理
- 边界是否清晰
- 是否考虑了依赖关系

#### 并行与串行
> "哪些步骤可以并行，哪些必须串行？"

考察点：
- 依赖关系识别
- 临界路径规划
- 资源冲突处理

---

### Level 4：多 Agent 管理

#### Context 隔离
> "当多个 Agent 同时工作时，如何避免它们互相污染上下文？"

考察点：
- Context 隔离机制设计
- 状态管理策略
- 信息传递协议

#### 结果复用
> "如何保证结果可以被复用，而不是每次都从头再来？"

考察点：
- 中间状态存储设计
- 缓存策略
- 增量更新机制

---

### Level 5：表达结构压缩

#### Prompt 工程
> "如何把一个复杂问题压缩成可以被 AI 快速理解和执行的表达结构？"

考察点：
- 信息密度控制
- 结构化表达能力
- 示例设计技巧

#### Context 设计
> "怎么设计 context，怎么做中间状态的存储和裁剪？"

考察点：
- Context Window 管理
- 关键信息提取
- 噪声过滤策略

---

### Level 6：失败处理机制

#### 兜底设计
> "AI 会出错，这是确定性的。你有没有设计好兜底机制？"

考察点：
- 失败模式识别
- 关键节点校验设计
- 回滚策略

#### 偏差感知
> "是让 AI 一路撞墙，还是在关键节点就能感知偏差、及时纠偏？"

考察点：
- 监控指标设计
- 早期预警机制
- 自动纠偏策略

## 三、评估框架：如何打分？

### 能力雷达图

```
                    问题形态识别
                         |
                         |
    效率优化 -------+-------+------- 任务拆解
   (Token/时间)     |       |      (并行/串行)
                    |       |
                    +-------+
                   /    |    \
                  /     |     \
        失败处理 +      +      + 多 Agent 管理
                  \     |     /
                   \    |    /
                    +-------+
                         |
                    表达结构压缩
```

### 评分标准

| 维度 | 初级 (1-3) | 中级 (4-6) | 高级 (7-10) |
|------|-----------|-----------|------------|
| 效率优化 | 被动接受 AI 输出 | 能识别浪费并优化 | 系统性设计低 Token 方案 |
| 问题形态 | 直接开始编码 | 先分析再执行 | 重构问题本质 |
| 任务拆解 | 线性拆解 | 识别并行性 | 设计最优路径 |
| 多 Agent | 单 Agent 使用 | 简单多 Agent | 复杂编排与隔离 |
| 表达结构 | 自然语言描述 | 结构化 Prompt | 高密度精准表达 |
| 失败处理 | 事后修复 | 关键节点校验 | 系统性容错设计 |

## 四、面试流程设计

### 建议结构（90 分钟）

#### Phase 1：场景设定（10min）
给出一个真实业务场景，候选人需要用 AI 辅助完成。

#### Phase 2：实战观察（40min）
观察候选人如何使用 AI 工具：
- 第一步做什么
- 如何与 AI 交互
- 遇到错误如何处理

#### Phase 3：深度追问（30min）
基于刚才的实战，提出本文档 Level 1-6 的问题。

#### Phase 4：开放讨论（10min）
- 对 AI 编程工具的看法
- 最近发现的使用技巧
- 遇到的坑和解决方案

## 五、能力培养路径

### 新手 → 熟练
- 掌握单 Agent 高效使用
- 学会写结构化 Prompt
- 建立代码审查意识

### 熟练 → 精通
- 设计多 Agent 协作流程
- 掌握 Token 优化技巧
- 建立系统性测试思维

### 精通 → 专家
- 重构问题形态的能力
- 设计持续进化的系统
- 沉淀可复用的方法论

---

## 六、核心结论

> **过去优秀工程师的分水岭在"写得多快、写得多好"，现在更像是在看一个人能不能构建出一个持续产出的系统，让 AI 在里面稳定工作、不断进化。**

### 关键转变

| 维度 | 过去 | 现在 |
|------|------|------|
| 核心产出 | 代码 | 系统 |
| 竞争壁垒 | 编码速度 | 问题重构能力 |
| 价值体现 | 个人产出 | 团队杠杆 |
| 成长路径 | 技术深度 | 系统广度 |
